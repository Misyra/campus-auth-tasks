# 认证协议接入示例

这些示例用于把抓包结果转换成认证喵任务。门户地址、字段和密钥随学校部署变化，导入后应先用测试账号核对，不要把密码或 Cookie 写进任务文件。

## 深澜 SRUN BX1

仓库里的 [`srun-bx1-template`](../tasks/srun-bx1-template.json) 展示 `get_challenge → HMAC-MD5 / srun_info / SHA1 → srun_portal`。先修改两处 `10.0.0.1`，再按本校门户核对 `ac_id`、`n`、`type`、账号后缀和登录结果。`hmac_md5(challenge, password)` 的参数顺序是密钥在前、消息在后；普通 `md5(password + challenge)` 与其不等价。挑战值可从 JSON 或 JSONP 响应提取。模板只在请求完成后交给网络检测确认联网。

## GIWIFI：重定向参数与隐藏域

参考 [Warm-rain/giwifi](https://github.com/Warm-rain/giwifi) 的实际流程，不能只取 `page_time`、`sign` 就直接提交：还需要 `wifidog/get_auth_state` 返回的接入类型、站点编号、MAC 等字段。

1. 请求 `http://本机网关:8062/redirect`。若它返回跳转，勾选“停在重定向响应”，用 `redirect:gw_address`、`redirect:gw_port`、`redirect:mac`、`redirect:ip` 等规则从 `Location` 查询参数同时取值。若已经自动跳转到最终页，用 `url:gw_address` 等规则从最终 URL 取值。
2. 用这些参数请求 `http://login.gwifi.com.cn/cmps/admin.php/api/login/?…`，以 `html:page_time`、`html:sign` 从隐藏输入框提取值。步骤测试结果只显示变量名，不显示提取值。
3. 请求网关的 `/wifidog/get_auth_state`，取回 `access_type`、`station_sn`、`client_mac` 等字段。不同版本可能返回 JSON 字符串套 JSONP；这时先用 `regex:` 捕获响应，必要时改用浏览器任务或自定义脚本处理嵌套编码。
4. 组装 `loginaction` 表单；对账号、密码以及动态字段使用 `url_encode`，并在结果判断里配置失败标识。某些部署还需访问响应中的 `wifidog/auth` 地址才能完成认证，应增加后续请求步骤并将其作为结果判断依据。

这里展示的是**迁移路径**，不是已核对的跨校即用任务；请以本校抓包为准，不能把来源项目中的固定电话号码、网关地址直接照搬。

## 锐捷 / ePortal 的加密变体

先确认门户到底是哪一类：有的 `InterFace.do?method=login` 直接收表单，有的 `passwordEncrypt=true` 要求浏览器页面 JavaScript 先用 `queryString` 中的 MAC 和页面公钥做 RSA，还有的 `/eportal/portal/*` 使用完全不同的 `page_data_encrypt`。这些字段名相似，算法并不通用。

- 表单明文或普通摘要：用 HTTP 流程先提取 `queryString` / MAC，再在计算步骤生成表单字段。`queryString` 如需重复 URL 编码，要严格按页面实际请求编码次数处理。
- 页面 RSA / 动态公钥：优先用浏览器任务执行原页面逻辑。上海大学参考部署可在计算步骤调用 `shu_ruijie_password(ctx.password, ctx.vars.mac)`，其中 `mac` 应从当前页面 `queryString` 提取；它使用该部署的固定公钥。其他学校需要 HTTP 时，应针对**该校**把公钥来源与算法写入独立模板并用抓包向量验证。不要开启全局“锐捷加密”开关，让别的 ePortal 门户误用同一算法。
- 页面把“短信验证码”“扫码确认”作为第二步时，在浏览器任务提交后加 `{"id":"manual","type":"manual_check","value":"短信验证码"}`（或选择器）。命中后登录结果为“需要人工操作”，停止自动重试；登录后可由用户手工完成验证。

参考实现：[上海大学锐捷密码加密](https://github.com/BeiningWu/shu-net-keeper)；对应的 [`shu-ruijie-template`](../tasks/shu-ruijie-template.json) 展示参数提取与双重编码。该公钥与 MAC 拼接方式只能作为来源部署的证据，模板未在校园网环境实测。

## 802.1X、PPPoE 和私有 UDP

这些认证发生在网页 HTTP 之外。选择“脚本”登录渠道，调用已安装、已由用户配置的专用客户端；脚本通过 `CAMPUS_USERNAME`、`CAMPUS_PASSWORD` 等环境变量读取本次凭据，避免在命令行、任务 JSON 和日志中写明文密码。

| 类型 | 可用组件 | 任务边界 |
|---|---|---|
| 802.1X EAPoL | `wpa_supplicant`、mentohust、minieap 或校园官方客户端 | 需要网卡/驱动权限，脚本只负责启动和检查本次认证结果 |
| PPPoE | Windows 拨号连接、Linux `pppd` 或官方客户端 | 账号变形规则按运营商另行实现；成功后仍由认证喵检测公网连通性 |
| Dr.COM 等私有 UDP | 与本校协议匹配的专用客户端 | challenge 与心跳需要持续进程，不适合放在有超时的一次性登录脚本里 |

脚本退出码 `0` 表示本次动作完成，`2` 表示需要人工处理，`3` 表示凭据无效，其他非零退出码可按方案重试。持续心跳应由客户端自身服务或独立定时任务管理；不要让登录脚本无限循环，因为登录任务有超时与取消语义。调用外部程序时先验证其来源和参数传递方式，尤其不要把密码放进系统进程列表可见的命令行参数。
