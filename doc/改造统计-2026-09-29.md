# 社区仓库改造统计（2026-09-29）

> 背景：以「校园网」为关键词从 GitHub 收录了 355 个认证脚本仓库（见 `github-repos/INDEX.md`）。认证喵 v5.1.0 的直连渠道落地有序 HTTP 步骤（`schema_version: 2`）与 `hmac_md5` / `srun_info` 等计算函数后，对这批仓库做了一次许可证与协议分诊，把「已经可以适配」的部分改造为直连任务。本文是本轮改造的统计口径与结果清单；逐仓库的原始判定数据在 `temp/gh-search/triage.json`。

## 改造规则

| 规则 | 内容 |
|------|------|
| 署名保留 | 每个任务 `metadata.author` = 原仓库所有者，`metadata.source` = 原仓库地址，`metadata.license` = 许可证；索引条目同步带 `author` / `source` / `license` |
| 许可证门槛 | 只改造宽松许可证（MIT、Apache-2.0、BSD-2/3、WTFPL、木兰-PSL-2.0 等）；**严格许可证一律不动**：GPL/LGPL/AGPL 等 copyleft、CC-BY-NC 等限制条款、无许可证（保留所有权利）、自定义未知许可证 |
| 参数来源 | 网关、ac_id、运营商后缀等参数一律取自原仓库代码或 README 原文，不凭仓库名猜测；原 README 未写学校全称的在任务里注明 |
| 实测声明 | 所有改编任务均未在对应校园网环境实测，描述中注明「未实测」，导入后需用测试账号核对 |
| 协议边界 | 只改造 HTTP(S) 登录流程；802.1X EAPoL、PPPoE、私有 UDP（Dr.COM 3848 等）、CCTP 客户端协议按[认证协议接入示例](认证协议接入示例.md)的边界不改造为直连任务 |

## 差分测试（2026-09-30，3 个子代理并行）

为验证「改编任务渲染出的请求与原仓库实现一致」，搭建了差分测试台架（`temp/gh-search/test-harness/`）：`runner.mjs` 按执行器文档语义逐行移植运行任务（模板替换、transform 沙箱含 srun_info/hmac_md5 等内建函数——以 Rust 源测试向量自检、六种提取规则、跨步骤 Cookie），`mock_portal.py` 把原版与任务双方的请求录制到同一份日志并可服务端重算 srun chksum。原版能跑的直接跑起来对 mock 录制（Python/shell/curl/Node），跑不了的（Go/Rust/C#/Java/Kotlin）写带 `文件:行号` 标注的移植脚本；cup 甚至用真实编译的 Rust 二进制做了基准。

**结果：47 个任务全覆盖（46 个改编 + jcu 回归基线），27 PASS / 20 PASS_WITH_NOTES / 0 FAIL，无台架疑点；23 个任务在测试中被当场修复并复测通过。**

系统性发现（已全部按原版口径修复）：

1. **srun 的 hmd5 有三种真实口径**：`hmac_md5(token, "")`（BIT/HDU 等多版原版——空消息，不是 hmac(token,密码)）、`md5(challenge)`（云师大）、`md5(密码)`（清华）。
2. **Go/Rust 系原版的 info 内层 JSON 键为字典序**（acid/enc_ver/ip/password/username），与常见插入序实现不同，直接改变 srun_info 输出——清华/云师大/石油北京/广海阳江已对齐。
3. **编码普遍是两层**：门户预编码一次 + HTTP 客户端表单编码一次 = 线上双重编码；queryString/service 漏一层就会被服务端解错——upc/fzu/ysu/swu/shmtu/suse 已修复。
4. 石油北京实际默认 `ac_id=12、name=Windows 98`，北化工 os 固定为 "Windows 95"——以原仓库代码/配置为准。
5. 深大 `lang=zh`（原扩展 JS 重复键取后值，用未改动 JS 加 shim 实测证实）；重大缺 term_type/v、重师大缺 6 个 ACSetting 参数、中南表单版 v4serip 探测正则需兼容带引号形态——均已补齐。
6. **原版自身 bug 不复制**：桂电 GUI 会发出 `user@@telecom`（双 @），任务按其 mini_script 单 @ 口径；莆田学院原版把 headers 字典误作 requests 第二位置参数（UA/Cookie 全进了查询串），任务有意不收录——两条均记 PASS_WITH_NOTES。
7. 南信大 base64 密码需再过一次表单编码（base64 的 `+` 原样进表单会被解成空格）——测试后由维护者修复并复测通过。
